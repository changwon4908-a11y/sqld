데이터와 DB·DBMS

모든 내용의 출발점입니다. 데이터의 세 가지 형태와 DB·DBMS의 역할 구분만 잡으면 됩니다.

구분핵심예시
정형 데이터행(Row)·열(Column) 구조가 명확하게 정의됨 — 검색·정렬·집계가 빠름RDBMS의 테이블
비정형 데이터정해진 구조가 없어 즉시 분석이 어려움사진, 영상, 음성
반정형 데이터구조는 있으나 고정된 행·열 형태는 아님 — 태그·키-값 형태JSON, XML, HTML
DB논리적으로 연관된 데이터의 집합. 사용자가 직접 조작하지 않고 DBMS를 통해 접근쇼핑몰의 회원·주문 데이터 전체
DBMSDB를 생성·관리·제어하는 소프트웨어 — 무결성·보안·백업·동시 접근 처리 담당Oracle, MySQL, SQL Server

데이터 모델링 ★★★★ 빈출

현실 세계의 복잡한 데이터를 일정한 표기법으로 설계하는 과정입니다. 3대 특징과 유의점은 글자 그대로 암기하세요.

  • 모델링 3대 특징 (단·추·명): 단순화 · 추상화 · 명확화 — 거의 매회 출제
    • 단순화: 불필요한 요소 제거 / 추상화: 복잡한 현실을 이해하기 쉬운 구조로(ERD 활용) / 명확화: 누구나 같은 뜻으로 읽게 정의
  • 모델링 관점 3가지: 데이터 관점 · 프로세스 관점 · 상관(데이터↔프로세스) 관점
  • 모델링 유의점 중복(Duplication) · 비유연성(Inflexibility) · 비일관성(Inconsistency) — 이 셋을 피해야 함
    • 비유연성: 업무가 바뀔 때 구조 수정이 어려운 설계 — 프로그램과 데이터 구조를 분리해 예방

모델링 3단계 순서 문제 매회 출제

추상화 수준이 높은 것부터: 개념적 → 논리적 → 물리적 순서입니다.

단계하는 일특징
개념적 모델링주요 엔터티와 관계 도출, 전체 구조 파악(ERD)추상화 수준 최고, 상세보다 대략적
논리적 모델링속성 정의, 관계 설정(FK 반영), 정규화 수행특정 DBMS에 종속되지 않음
물리적 모델링실제 데이터 타입 지정, 인덱스·저장공간·보안 설계특정 DBMS에 종속, 성능 중심

3단계 스키마와 데이터 독립성

스키마란 DB의 구조·제약조건에 대한 전반적인 명세입니다. 보는 관점에 따라 3층으로 나눕니다.

스키마관점핵심
외부 스키마사용자 뷰서브 스키마라고도 함. 하나의 DB에 여러 개 존재 가능, 보통 뷰(View)로 구현
개념 스키마전체 뷰DB 전체의 논리 구조. 하나의 DB에 하나만 존재
내부 스키마저장(물리) 뷰실제 저장 구조·인덱스·접근 경로를 명세
  • 논리적 독립성: 개념 스키마가 변해도 외부 스키마는 영향 없음
  • 물리적 독립성: 내부 스키마가 변해도 외부·개념 스키마는 영향 없음

ERD 작성 순서 ★★★ 도·배·설·명·참·여

1976년 피터 첸(Peter Chen)이 제안한, 엔터티·속성·관계를 시각화하는 도구입니다. 작성 순서를 묻는 문제가 나옵니다.

① 엔터티 도출→ ② 엔터티 배치→ ③ 관계 설정→ ④ 관계명 기술→ ⑤ 관계 참여도→ ⑥ 필수 여부

엔터티(Entity) ★★★ 빈출

업무에서 관리해야 할 대상(사람·사물·개념·사건)입니다. "엔터티의 특징으로 틀린 것"을 고르는 문제가 단골입니다.

  1. 서로 구분(식별) 가능해야 한다 → 유일한 식별자 존재
  2. 업무에 꼭 필요한 정보여야 한다
  3. 인스턴스가 2개 이상(다수)인 집합이어야 한다
  4. 속성을 2개 이상 가져야 한다
  5. 다른 엔터티와 관계를 1개 이상 가져야 한다 (코드성·통계성 엔터티는 예외)
  6. 업무 프로세스에서 사용되어야 한다
왜 "2개 이상"인가?
교재에 따라 "하나 이상의 속성"으로 완화해 쓴 곳도 있지만, SQLD 기출 정답 기준은 "엔터티는 2개 이상의 속성을 갖는다"가 옳은 지문입니다. 식별자 속성 + 대상을 설명하는 일반 속성이 최소한 있어야 하기 때문입니다. 인스턴스도 2개 이상이어야 "집합"이 됩니다.
분류 기준종류설명예시
실체 유형
유·개·사		유형 엔터티물리적으로 존재, 눈으로 확인 가능학생, 사원, 고객, 제품
개념 엔터티물리적 형태 없이 업무상 관리가 필요한 추상적 존재강의, 부서, 직급, 자격증
사건 엔터티특정 시점에 발생하는 행위·업무 결과주문, 결제, 수강신청
발생 시점
기·중·행 ★		기본 엔터티독립적으로 존재 가능, 가장 먼저 생성됨고객, 제품, 사원
중심 엔터티업무의 핵심, 기본과 행위 엔터티를 연결주문, 진료, 수강
행위 엔터티두 개 이상의 부모 엔터티로부터 발생판매, 배송, 결제, 환불

속성(Attribute) ★★★★ 빈출

엔터티를 구성하는 가장 작은 데이터 단위입니다. 특성 기준 3분류(기·설·파)가 매회 출제됩니다.

구분의미예시
기본 속성업무에서 원래부터 자연스럽게 존재하던 정보이름, 생년월일, 주소, 상품가격
설계 속성설계 과정에서 인위적으로 만들어 붙인 정보상품코드, 회원등급, 일련번호(인조식별자)
파생 속성다른 속성에서 계산되어 나온 정보 — 정합성 문제가 생기므로 되도록 적게 정의나이(←생년월일), 합계금액(←주문내역)
  • 구조 기준: 단순 속성(더 못 쪼갬) / 복합 속성(주소=시+구+동) / 다중값 속성(취미 여러 개 → 정규화로 별도 엔터티 분리)
  • 도메인(Domain): 속성이 가질 수 있는 값의 범위 — 타입·길이·형식·허용값으로 정의하며 무결성을 강화

관계(Relationship)

엔터티와 엔터티 사이의 논리적 연결입니다. 관계를 기술하는 세 가지 요소를 기억하세요.

  • 관계 표기 3요소: 관계명(동사형) · 관계차수(1:1, 1:N, M:N) · 선택사양(필수/선택)
  • 참여도(선택사양): 엔터티가 그 관계에 반드시 참여해야 하는지(필수) 아닌지(선택)
  • 존재에 의한 관계(학과-학생: 강한 의존) vs 행위에 의한 관계(고객-상품 '구매': 독립적 존재 가능)
  • M:N 관계는 관계형 DB에서 직접 구현 불가 → 교차(연관) 엔터티로 1:N 두 개로 해소 — 빈출

식별자 ★★★ 빈출

엔터티 안의 인스턴스를 유일하게 구분하는 속성(조합)입니다. 특징 4가지와 분류, 식별자/비식별자 관계까지 모두 자주 나옵니다.

  • 식별자 4대 특징 (유·최·불·존): 유일성 · 최소성 · 불변성 · 존재성(NULL 불가) — 매회 출제
분류 기준종류
대표성 여부주식별자(대표, 테이블당 1개) / 보조식별자
스스로 생성 여부내부식별자(주문번호) / 외부식별자(다른 엔터티에서 온 FK)
속성 수단일식별자 / 복합식별자(2개 이상 조합)
대체 여부 ★★본질식별자(업무에서 원래 존재: 주민번호) / 인조식별자(시스템이 인위 부여: 주문번호, 시퀀스)
인조식별자 보충 — 7회 시험에서 4문항 출제
복합식별자가 길고 복잡할 때 단일 인조식별자(예: 시퀀스)로 대체하면 자식 테이블로의 식별자 전파와 조인이 단순해집니다. 대신 단점: ① 업무적 의미가 사라짐 ② 인조키가 달라도 같은 본질값인 중복 데이터 발생 가능 ③ 그래서 본질식별자 조합에 UNIQUE 제약을 따로 걸어 보완해야 함. "시퀀스로 채번한 주문일련번호는 본질식별자다"는 틀린 지문(인조식별자)입니다.
구분식별자 관계비식별자 관계
부모 PK가 자식의PK에 포함됨일반 속성(FK)으로만 들어감
표기실선점선

릴레이션 용어 ★ 카디널리티/차수 함정

관계형 모델(1970, E.F.Codd)의 수학 용어와 일상 용어를 짝지으세요. 카디널리티와 차수를 바꿔 내는 함정이 많습니다.

용어의미동의어
릴레이션행·열로 된 2차원 표테이블
튜플한 행(하나의 인스턴스)행(Row), 레코드
속성한 열(데이터 항목)열(Column), 필드
카디널리티튜플(행)의 수행 수
차수(Degree)속성(열)의 수열 수

릴레이션의 특징: 튜플 유일성·무순서, 속성 무순서·원자성, 속성명 유일성.

키(Key)의 종류 ★★ 빈출

포함 관계로 이해하면 외울 게 줄어듭니다: 유일성만 있으면 슈퍼키 → 최소성까지 갖추면 후보키 → 대표가 기본키, 나머지가 대체키.

키정의조건
슈퍼키튜플을 유일하게 식별하는 속성 집합유일성만 (최소성 불필요)
후보키슈퍼키 중 최소성까지 만족유일성 + 최소성
기본키(PK)후보키 중 대표로 선택유일성 + 최소성 + NOT NULL, 테이블당 1개
대체키PK로 선택되지 않은 나머지 후보키UNIQUE 제약으로 구현 가능, 복합 속성도 가능
외래키(FK)다른 테이블의 PK를 참조참조 값과 일치하거나 NULL

무결성 제약조건 ★ 빈출

"잘못된 데이터가 들어오지 못하게 막는 규칙"입니다. 네 종류의 이름과 담당 범위를 짝지으세요.

무결성규칙구현 수단
개체 무결성PK는 NULL 불가 + 중복 불가PRIMARY KEY
참조 무결성FK는 참조 대상 PK 값과 일치하거나 NULLFOREIGN KEY
도메인 무결성속성값이 정의된 타입·범위·허용값을 따름CHECK, NOT NULL, DEFAULT
사용자 정의 무결성업무 규칙을 직접 정의 (예: 가격 > 0)트리거, CHECK 등

FK 참조 무결성 옵션 (ON DELETE) 빈출

이게 왜 1과목에 나오나요?
2024년 개편 후 1과목 2장이 "데이터 모델과 SQL"이라서 참조 무결성과 ON DELETE 옵션은 정식 1과목 범위입니다. 상황: 부모 테이블(학생)의 행을 지우려는데 자식 테이블(수강)이 그 학번을 FK로 참조 중이라면? 그때 자식을 어떻게 처리할지 미리 정하는 선택지가 아래 4가지이고, FK 정의 시 REFERENCES 학생(학번) ON DELETE CASCADE처럼 붙입니다.
옵션부모 행 삭제 시 동작예: 학생 S001 삭제하면
CASCADE참조하던 자식 행도 함께 삭제S001의 수강 기록도 모두 삭제
SET NULL자식의 FK 값을 NULL로 변경 (행은 유지)수강 기록의 학번만 NULL로
SET DEFAULT자식의 FK를 미리 정한 기본값으로 변경학번이 기본값으로 바뀜
RESTRICT / NO ACTION자식이 참조 중이면 부모 삭제 자체를 거부 (기본)S001 삭제가 실패함

Oracle은 ON DELETE 옵션만 지원하고 ON UPDATE는 지원하지 않습니다.

SQL 문장 분류 ★★★ 거의 매회

명령어가 어느 분류인지 묻는 문제가 매회 2~3문항 나옵니다. 표를 통째로 암기하세요.

분류명령어특징
DDL (정의어)CREATE, ALTER, DROP, TRUNCATE, RENAME자동 COMMIT → ROLLBACK 불가
DML (조작어)SELECT, INSERT, UPDATE, DELETE, MERGE자동 COMMIT 안 됨
DCL (제어어)GRANT, REVOKE권한 부여·회수
TCL (트랜잭션)COMMIT, ROLLBACK, SAVEPOINT트랜잭션 확정·취소
함정 TRUNCATE는 데이터를 지우지만 DDL입니다(DELETE만 DML). SELECT를 DQL로 따로 나누는 책도 있지만 시험에서는 보통 DML에 포함합니다.

정규화 ★★★ 최다 빈출

데이터 중복을 없애려고 테이블을 분해하는 과정입니다. "몇 정규형 위반?"을 묻는 판별 문제가 매회 나옵니다.

이상현상(Anomaly) 3가지

  • 삽입 이상: 원치 않는 데이터까지 함께 넣어야만 삽입 가능 (수강생 없는 신설 과목을 등록 못 함)
  • 갱신 이상: 중복된 값 일부만 수정되어 불일치 발생 (학과 사무실 이전 시 모든 행 수정 필요)
  • 삭제 이상: 삭제하면 안 되는 정보까지 같이 사라짐 (수강 취소하니 학생 정보도 삭제)

함수적 종속 (A → B: A가 B를 결정)

  • 완전 함수 종속: 복합키 전체가 있어야 결정 — (학번, 과목코드) → 성적
  • 부분 함수 종속: 복합키 일부만으로 결정 — 학번 → 학생명 → 2NF 위반 신호
  • 이행 함수 종속: A→B→C로 간접 성립 — 학번→학과→학과사무실 → 3NF 위반 신호
정규형제거 대상판별 암기
1NF비원자값(다중값·복합값)모든 속성이 원자값 — 한 칸에 전화번호 2개면 위반
2NF부분 함수 종속복합키 일부에만 종속된 속성이 있으면 위반 (단일키면 자동 만족)
3NF이행 함수 종속일반속성 → 일반속성 종속이 있으면 위반
BCNF결정자가 후보키가 아닌 종속모든 결정자가 후보키 (3NF 강화형)
4NF / 5NF다치 종속 / 조인 종속출제 빈도 낮음 — 이름만

반정규화(Denormalization) ★ 빈출

  • 조회 성능을 위해 의도적으로 중복 허용 — 무결성 관리 부담은 증가
  • 적용 시점: 빈번한 조인 · 통계/집계 반복 계산 · 대용량 조회 성능 문제
  • 기법: 테이블 병합/분할(수평·수직), 중복 테이블·컬럼 추가, 파생 컬럼 추가(합계 미리 저장), 이력 테이블 분리

슈퍼타입 · 서브타입 ★ 7회 2문항

공통 속성은 슈퍼타입에, 고유 속성은 서브타입에 두는 모델링입니다. 예: 직원(슈퍼) — 정규직/계약직(서브).

  • 배타적(Exclusive): 한 인스턴스는 최대 하나의 서브타입에만 속함
  • 포괄적(Inclusive): 한 인스턴스가 여러 서브타입에 동시에 속할 수 있음
  • 완전성 제약: 모든 슈퍼타입 인스턴스가 어느 서브타입이든 반드시 속해야 함
  • 물리 변환 3유형: All-in-One(한 테이블 통합 — 조인 없음, 구분자 필요) / 슈퍼+서브(Plus)(슈퍼 1개 + 서브별 테이블) / One-to-One(서브타입별 개별 테이블, 정규화 수준 높음)

SELECT 실행 순서 ★★★ 거의 매회

작성 순서(SELECT부터)와 실행 순서는 다릅니다. 이 순서가 "별칭을 어디서 쓸 수 있나"를 결정합니다.

① FROM→ ② WHERE→ ③ GROUP BY→ ④ HAVING→ ⑤ SELECT→ ⑥ ORDER BY
  • SELECT가 5번째 → 별칭(Alias)은 그보다 뒤인 ORDER BY에서만 사용 가능
  • WHERE가 GROUP BY보다 앞 → WHERE에는 집계함수 불가, 그룹 조건은 HAVING으로

자료형 (Oracle)

CHAR vs VARCHAR2 비교가 빈출입니다. 핵심은 "뒷공백을 어떻게 다루느냐"입니다.

항목CHAR(n) — 고정 길이VARCHAR2(n) — 가변 길이
저장n만큼 항상 차지, 모자라면 공백으로 채움입력한 길이만큼만 사용
비교 ★★뒷공백 무시 — 'ABC' = 'ABC ' 참그대로 비교 — 'ABC' ≠ 'ABC '
용도길이 고정 값(주민번호 등)길이 가변 값(이름, 주소)
  • NUMBER(P,S): 전체 P자리 중 소수점 이하 S자리 — NUMBER(5,2)에 123.456 → 123.46 반올림 저장
  • DATE: 연월일시분초 모두 저장(7바이트) / TIMESTAMP: 소수점 이하 9자리 초까지
  • 대용량: CLOB(문자), BLOB(이진) — 각 최대 4GB

제약조건 ★★ NULL·중복 비교

제약조건NULL중복개수 / 비고
PRIMARY KEY불허불허테이블당 1개, 자동 인덱스

NOT NULL + UNIQUE = PK와 거의 같은 효과. 차이: PK는 1개뿐, 이 조합은 여러 컬럼 가능.

세 가지 "지우기"의 차이를 묻는 문제가 단골입니다. 분류와 ROLLBACK 가능 여부가 핵심입니다.

  • 길이 축소는 기존 데이터가 다 들어갈 때만, NOT NULL 추가는 기존에 NULL이 없을 때만
  • UNIQUE 추가는 기존 데이터에 중복이 있으면 실패 (7회 출제)

DML: INSERT · UPDATE · MERGE

  • INSERT 컬럼 목록 생략 시 → 모든 컬럼을 정의 순서대로 입력
  • INSERT INTO 대상 SELECT ...: 조회 결과를 그대로 삽입 (대량 이관) — VALUES 절 없음
  • UPDATE는 SET 컬럼1 = 값1, 컬럼2 = 값2 쉼표 연결 (AND 아님! — 7회 출제)
  • CTAS(CREATE TABLE AS SELECT): 제약조건은 NOT NULL만 복사 (PK·FK·UNIQUE·CHECK·인덱스 미복사)
MERGE — 있으면 UPDATE, 없으면 INSERT 
MERGE INTO 대상 T USING 원본 S ON (T.ID = S.ID)
WHEN MATCHED     THEN UPDATE SET T.QTY = T.QTY + S.QTY
WHEN NOT MATCHED THEN INSERT (ID, QTY) VALUES (S.ID, S.QTY);
매칭된 행은 UPDATE, 아닌 행은 INSERT. 결과 행 계산 문제로 출제 — 6회: (1,100)에 (1,50),(2,30) 병합 → (1,150),(2,30).

WHERE 절 연산자 ★ 빈출

  • BETWEEN A AND B: A 이상 B 이하 (경계값 포함)
  • IN (a,b,c): 목록 중 하나와 일치
    • NOT IN 목록에 NULL이 있으면 결과는 항상 공집합(0건) — 오류가 아님
  • LIKE 와일드카드
    • % = 0글자 이상 / _ = 정확히 1글자
    • '김_'은 두 글자 이름만, '김%'는 김으로 시작하는 모두 — 글자 위치를 짚어가며 세기
  • 논리 우선순위: NOT > AND > OR — 괄호 없는 혼합식 문제 빈출
  • NULL 비교는 IS NULL / IS NOT NULL만 (= NULL은 항상 0건)

함수동작예시

  • CASE WHEN 조건 THEN 값 … ELSE 값 END — ELSE 생략 시 NULL
  • DECODE(컬럼, 값1, 결과1, …, 기본값): Oracle 전용, 등호 비교만 — NULL = NULL을 같다고 처리 (CASE와 다름)

집계함수 · GROUP BY · HAVING ★★★ 매회

  • 집계함수는 NULL 제외 계산 — 단 COUNT(*)만 NULL 포함 전체 행 수
  • COUNT(컬럼) = NULL 제외 / COUNT(DISTINCT 컬럼) = 중복 제거 개수
  • AVG도 NULL 제외 평균 → NVL(컬럼,0)로 감싸면 분모가 달라져 결과가 바뀜
  • GROUP BY 시 SELECT·ORDER BY에는 그룹 컬럼 + 집계함수만 (다른 컬럼이 오면 오류 — 7회 출제)
  • WHERE = 그룹화 전 행 조건 / HAVING = 그룹화 후 그룹 조건 — 바꿔치기 문제 빈출

ORDER BY · DISTINCT

  • 기본 오름차순(ASC). Oracle은 NULL을 가장 크게(ASC 마지막), SQL Server는 가장 작게(ASC 처음) — DBMS 비교 출제
  • NULLS FIRST / NULLS LAST로 변경 가능
  • 컬럼 순번(ORDER BY 2)·별칭 사용 가능 — 실행 순서상 마지막 절이라서
  • DISTINCT는 SELECT 뒤 전체 컬럼 조합 기준 중복 제거

JOIN ★★★ 매회

결과 행 수를 세는 계산 문제가 반드시 나옵니다. 기준 테이블이 어느 쪽인지부터 확인하세요.

  • N개 테이블 조인의 최소 조인 조건 수 = N - 1개

쿼리 안의 쿼리입니다. "어디에 쓰였나(위치)"와 "몇 행을 돌려주나"로 분류합니다.

ROLLUP · CUBE · GROUPING SETS ★★★ 매회

GROUP BY에 소계·합계를 얹는 확장입니다. "결과가 몇 행인가"를 꼭 계산해 보세요.

함수생성되는 집계 (A,B 기준)그룹 수
ROLLUP(A,B)(A,B) + (A) + 전체합계 — 계층적, 순서 중요3종류
CUBE(A,B)(A,B) + (A) + (B) + 전체합계 — 모든 조합, 순서 무관4종류 (2ⁿ)
GROUPING SETS(A,B)지정한 집합만 — 전체합계는 ()로 따로지정한 만큼
GROUPING / GROUPING_ID 읽는 법 (7회 출제)
집계 행에서는 해당 컬럼이 NULL로 나오는데, "진짜 NULL"인지 "집계라서 NULL"인지 구분해 주는 함수입니다.
· GROUPING(컬럼): 집계(소계) 행이면 1, 상세 행이면 0
· GROUPING_ID(A,B): 두 값을 2진수로 묶음 — 상세 00=0, A별 소계 01=1, 전체합계 11=3

윈도우 함수 ★★★ 매회

OVER 구문 해부 — 세 조각뿐입니다 
함수() OVER ( PARTITION BY 그룹컬럼  -- ① 어떤 그룹 안에서
              ORDER BY 정렬컬럼      -- ② 어떤 순서로
              ROWS BETWEEN ... )     -- ③ 어느 범위(프레임)를 계산
GROUP BY와 달리 행이 줄지 않고 각 행 옆에 결과가 붙습니다. ①이 없으면 전체가 한 그룹입니다.
순위 함수동점 처리예: 100, 100, 90
RANK()동점 뒤 순위 건너뜀1, 1, 3
DENSE_RANK()동점 뒤에도 연속1, 1, 2
ROW_NUMBER()동점이어도 고유 번호1, 2, 3
  • 행 순서: LAG(이전 행), LEAD(다음 행), FIRST_VALUE, LAST_VALUE
  • 비율: RATIO_TO_REPORT(전체 대비), PERCENT_RANK = (RANK-1)/(전체행-1) — 공동 1위는 0 (7회 출제), NTILE(n등분)
  • 이동 집계: ROWS BETWEEN 1 PRECEDING AND CURRENT ROW — 프레임은 "정렬 후 행 위치" 기준이라 동점이어도 행마다 결과가 다를 수 있음 (6회 출제)

TOP-N 쿼리 ★ 빈출

  • ROWNUM은 정렬 전에 붙는다 → 인라인 뷰에서 ORDER BY 후 바깥에서 ROWNUM 조건
  • ROWNUM >= 2 단독 조건은 항상 0건 (1부터 순차 부여)
  • 표준: FETCH FIRST n ROWS ONLY / SQL Server: TOP(n)

계층형 질의 (Oracle) ★★ 빈출

사원-관리자처럼 한 테이블 안의 부모-자식 구조를 트리로 펼치는 문법입니다.

SELECT LEVEL, 사원명
FROM   사원
START WITH 관리자ID IS NULL          -- 루트(시작점)
CONNECT BY PRIOR 사원ID = 관리자ID;  -- 부모 → 자식 연결
  • LEVEL: 계층 깊이 의사컬럼, 루트가 1 (0 아님 — 7회 출제)
  • PRIOR 해석이 핵심: PRIOR가 붙은 쪽이 부모 행 — PRIOR 자식PK = 부모FK면 순방향(부모→자식)
  • 보조: ORDER SIBLINGS BY, SYS_CONNECT_BY_PATH, CONNECT_BY_ISLEAF, NOCYCLE

PIVOT · UNPIVOT · 정규표현식

  • PIVOT: 행 → 열 / UNPIVOT: 열 → 행
    • 결과 크기: 학생 2명 × 과목 3열 UNPIVOT → 6행 3열 (6회 출제)
    • UNPIVOT은 NULL 행 기본 제외(INCLUDE NULLS로 포함). 대상 열 타입이 다르면 오류
  • 정규표현식 REGEXP_LIKE·SUBSTR·INSTR·REPLACE·COUNT (COUNT는 횟수만 반환)
    • ^시작 $끝 .임의 1자 *0회+ +1회+ ?0~1회 [abc]집합 [^abc]부정 {m}m회 |또는
    • 영문 3글자+숫자 2글자 = [A-Z]{3}[0-9]{2} (7회 출제)

뷰(View) ★ 빈출

  • 실제 데이터를 저장하지 않는 가상 테이블 — 정의 SELECT문만 데이터 사전에 저장
  • 조회 때마다 정의 쿼리 재실행 → 원본 변경이 즉시 반영
  • 장점: 복잡한 쿼리 단순화(편리성), 민감 컬럼 노출 제한(보안성), 독립성
  • 뷰 자체에 인덱스 불가, 기반 테이블 인덱스는 활용

트랜잭션 · ACID · TCL ★★★ 매회

트랜잭션 = "전부 성공 아니면 전부 취소"로 처리되는 논리적 작업 단위. 네 속성의 설명을 바꿔치기해 출제합니다.

    • 단, 두 경로로 받았다면 한 경로 회수돼도 다른 경로 권한은 유지 (7회 출제)

  • ROLE: 여러 권한을 묶어 일괄 부여

함정 1. NULL 관련 최다 빈출

  • NOT IN (목록에 NULL 포함) → 결과는 항상 공집합(0건)
    • 오류·연산불가가 아닙니다. x NOT IN (a, NULL) = x<>a AND x<>NULL인데 x<>NULL이 UNKNOWN이라 어떤 행도 참이 못 됨
    • 반면 IN은 NULL이 있어도 정상 동작 (OR 조건)
  • NULL 비교는 IS NULL / IS NOT NULL만 — = NULL은 항상 0건
  • NULL이 섞인 산술 연산 결과는 항상 NULL
  • 집계함수는 NULL 제외 — COUNT(*)만 NULL 포함, AVG는 NVL 처리 여부로 값이 달라짐
  • Oracle은 ''(빈 문자열)도 NULL / SQL Server는 빈 문자열
  • 정렬: Oracle NULL 최대(ASC 마지막) / SQL Server NULL 최소(ASC 처음)
  • DECODE는 NULL = NULL을 같다고 처리 (CASE와 다름)
  • PK는 NULL 불허 / UNIQUE는 NULL 허용(Oracle은 여러 개)

함정 2. 절(Clause)별 사용 제한

  • WHERE에 집계함수 불가 → 그룹 조건은 HAVING
  • SELECT 별칭은 ORDER BY에서만 사용 가능
  • GROUP BY 시 SELECT·ORDER BY에는 그룹 컬럼 + 집계함수만
  • 윈도우 함수는 WHERE·GROUP BY·HAVING에 불가 → 순위 필터링은 인라인 뷰로
  • 집합연산자의 ORDER BY는 맨 마지막 한 번만 / 서브쿼리 안 ORDER BY 불가(일반적)
  • 다중행 서브쿼리에 =, >, < 사용 시 오류 → IN / ANY / ALL / EXISTS
  • ROWNUM은 정렬 전 부여 → ORDER BY와 함께면 인라인 뷰 필수, ROWNUM ≥ 2 단독은 0건
  • CHECK 제약에 서브쿼리·SYSDATE·다른 행 참조 불가
  • NATURAL JOIN / USING 대상 컬럼에 별칭·접두어 금지

함정 3. DDL · 트랜잭션

  • DDL은 자동 커밋 → ROLLBACK 불가
    • 트랜잭션 중간에 DDL이 끼면 이전 DML까지 함께 확정
    • 예외: PostgreSQL은 트랜잭션 내 DDL ROLLBACK 가능
  • DELETE는 커밋 전 ROLLBACK 가능 / TRUNCATE·DROP은 불가
  • ROLLBACK TO sp 후에도 sp 이전 작업·SAVEPOINT는 유지
  • 제약 위반 INSERT는 그 문장만 실패, 트랜잭션은 계속
    • 단, 보기에 '오류 발생'이 있으면 제약 위반 자체가 정답일 수 있음 (7회 실제 출제 — 보기 구성을 보고 판단)
  • DEFAULT는 컬럼 생략 시에만 — 명시적 NULL이면 NULL 저장
  • CTAS는 NOT NULL만 복사 (PK·FK·UNIQUE·CHECK·인덱스 미복사)
  • NOT NULL 추가는 기존 NULL이 없을 때만 / UNIQUE 추가는 기존 중복이 없을 때만

함정 4. 함수 · 비교 연산

  • CHAR는 뒷공백 무시('ABC'='ABC ' 참) / VARCHAR2는 그대로 비교(거짓)
  • SUBSTR(문자열, 시작, 개수) — 시작이 음수면 뒤에서부터
  • NUMBER(p,s): s 초과 소수는 반올림 (123.456 → 123.46)
  • CEIL(-15.7) = -15, FLOOR(-15.7) = -16 — 음수 방향 주의
  • 논리 우선순위 NOT > AND > OR — 괄호 없으면 AND가 먼저
  • RANK(건너뜀) / DENSE_RANK(연속) / ROW_NUMBER(고유) — 동점 처리로 구분
  • UNION(중복 제거·느림) vs UNION ALL(중복 포함·빠름) — 행 수 비교 빈출
